## 1/1 목

### 설계 전 고려사항 (3-4일의 짧은 기간을 고려)
1. 에이전트 종류 결정
    a. 범용 에이전트 (open deep research 언급)
    b. 특정 도메인 에이전트 ("서비스" 개발 및 개발 이유 작성 명시) => **선택**
    - => "b"로 설정
    - 이유: 범용에이전트보다 높은 성능은 현실적으로 쉽지 않아보이고, 잘못하면 클론코딩수준밖에 안될 수 있음

2. 도메인 결정
    - **"연구/기술 트렌드 리서치 에이전트"**로 결정
    - 지금까지 진로의 방향이나, 최근 연구실에 들어가며 연구 주제나 방향을 결정할 때 구글링등을 통해 트렌드나 시장, 잡 마켓 크기등을 많이 탐색해왔음. 이 때 들었던 시간을 해결하고자 함
    - 문제: 결과에 대한 신뢰성이 확보되어야 함

3. 아키텍처 결정
    - frontend: vanilla js + html
        - 이유: streamlit으로 간단하게 표현하려 했지만, 웹으로 보여줄 때, 실행 시간이 오래걸릴걸 예상해서 SSE방식으로 중간 단계를 표현해 주거나, 에이전트 실행 로그를 보여주기 위함
    - backend: fastapi + langgraph
    - deployment: 간단하게 ec2+nginx, 개인 도메인 이참에 하나 구매할 예정
    - db/vectordb: 개발 초기단계에서는 인메모리로 개발, 에이전트 뼈대 먼저 잡고 고민

4. 에이전트 패턴 결정
    - 최소 뼈대: 의도파악-정보수집-결과생성
    - 정보수집에 필요한 데이터소스: 논문 아카이빙 API + 웹 검색 API + 필요 시 간단한 스크래퍼정도
